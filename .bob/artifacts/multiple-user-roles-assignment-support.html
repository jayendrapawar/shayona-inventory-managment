Multiple Roles Support Implemented

Users can now be assigned multiple roles, allowing seamless access across modules (e.g., Admin + Picker, Picker + Accountant).
Admin Accountant Salesman Picker Dispatcher No Role
✨ Key Features Implemented
  • Multi-role Database Serialization: Stores roles as a clean comma-separated string (e.g. "admin,picker") in the existing schema, avoiding any migration overhead.
  • Interactive Multi-role Selector: Replaced the rigid single-select <select> element in Master Dashboard with a custom, lightweight multi-select dropdown that updates roles instantly.
  • Pill-badge Grouping: Upgraded the RolePill component to dynamically render separate colorful badges side-by-side for each active role.
  • Robust Route-level Guard Checking: Enhanced all page.tsx server-side route checks to split and search the roles array, granting access if the user has any authorized role.
  • Priority Redirects: Multi-role users accessing /orders are automatically routed to the highest-priority page they are eligible for: Admin → Salesman → Picker → Dispatcher.
  • Search and Stats Compatibility: Updated database query methods using like() matching and dashboard counters to accurately tally users in overall metrics across any permutation of roles.
🚀 Core File Changes Overview
  • app/actions/users.ts: Upgraded getUsersByRole, getPickersList, updateUserRole, and getCurrentUserRole to be compatible with multiple role strings.
  • app/actions/orders.ts: Modified requireRole and individual access check filters to handle comma-separated role checks.
  • components/home-menu-page.tsx: Enhanced the homepage card layout to filter visible tiles based on the array intersection of user roles and page role allowances.
  • app/master/master-dashboard.tsx: Added a beautiful absolute-positioned RoleSelector dropdown that works smoothly on both Desktop and Mobile views.
  • app/orders/_components/shared.tsx: Reimplemented RolePill to split comma-separated text into separate badges.
